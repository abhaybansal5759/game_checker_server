# Checkers Game Server

A production-grade single Go server for online checkers with:
- **Guest login** + **Google OAuth** (via Firebase) — user ID stays the same when a guest upgrades
- **Bot mode** (minimax AI, configurable depth)
- **Multiplayer matchmaking** (long-poll queue)
- **Elo rating** (chess.com-style K-factor tiers)
- **Leaderboard** with MongoDB persistence
- **Token-bucket rate limiting** per IP
- **WebSocket** real-time gameplay
- Free deploy on **Render** + **MongoDB Atlas**

---

## Architecture

```
Client
  │
  ├─ HTTP ──► Auth Routes    (/auth/guest, /auth/google, /auth/me)
  │            Profile Routes (/profile/name)
  │            Leaderboard   (/leaderboard)
  │            Matchmaking   (/matchmaking/join, /matchmaking/leave)
  │            Game          (/game/bot, /game/:id, /game/:id/resign)
  │
  └─ WS ───► /ws?token=<jwt>&game_id=<id>   Real-time moves
```

All HTTP routes are rate-limited by a **token bucket** (per IP):
- General routes: 10 req/s, burst 30
- Auth routes: 2 req/s, burst 5 (protects against brute-force)
- WebSocket messages: 5 msg/s, burst 10 per connection

## MongoDB Atlas Setup (Free Tier)

1. Go to https://cloud.mongodb.com and sign up free
2. Create a **free M0 cluster** (512 MB, enough for thousands of users)
3. In **Database Access** → Add a user with password auth → note the password
4. In **Network Access** → Add IP `0.0.0.0/0` (allow anywhere, needed for Render)
5. Click **Connect** → **Drivers** → Copy the connection string:
   ```
   mongodb+srv://myuser:mypassword@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
6. Replace `<password>` with your actual password
7. The server auto-creates these collections and indexes on first boot:
   - `users` — indexed on `user_id` (unique), `firebase_uid`, `rating`
   - `games` — indexed on `game_id` (unique), `white_user_id`, `black_user_id`

## Firebase Setup (for Google Login)

1. Go to https://console.firebase.google.com
2. Create a project (or use existing)
3. Go to **Authentication** → Enable **Google** sign-in provider
4. Go to **Project Settings** → **Service Accounts** → Generate new private key
   - Download the JSON file
   - Name it `firebase-service-account.json` (never commit this to git)
5. Set environment variables:
   ```
   FIREBASE_PROJECT_ID=your-project-id
   GOOGLE_APPLICATION_CREDENTIALS=./firebase-service-account.json
   ```

**On Render:** Upload the service account JSON content as a secret file, or paste the JSON as an env var.

## Deploy on Render (Free)

1. Push your code to a GitHub repo
2. Go to https://render.com → New → Web Service
3. Connect your GitHub repo
4. Render auto-detects Go and uses `render.yaml`
5. Set environment variables in the Render dashboard:
   - `MONGO_URI` → your Atlas connection string
   - `FIREBASE_PROJECT_ID` → your Firebase project ID (optional)
   - `JWT_SECRET` → auto-generated by Render (`generateValue: true`)
6. Deploy — your server will be live at `https://your-app.onrender.com`

> **Free tier note:** Render free services spin down after 15 min of inactivity.
> First request after spin-down takes ~30s. Use UptimeRobot (free) to ping
> `/health` every 14 minutes to keep it warm.

## API Reference

### Authentication

#### `POST /auth/guest`
Create a guest account. Returns JWT token.

```json
// Request (all fields optional)
{ "display_name": "BravePawn1234" }

// Response 201
{
  "token": "eyJ...",
  "user_id": "a1b2c3d4-...",
  "display_name": "BravePawn1234"
}
```

#### `POST /auth/google`
Verify a Firebase Google ID token. Optionally merge a guest account.

```json
// Request
{
  "firebase_id_token": "<token from Firebase client SDK>",
  "guest_token": "<optional: your existing guest JWT to merge>"
}

// Response 200
{
  "token": "eyJ...",
  "user_id": "a1b2c3d4-...",   // same as guest if merged
  "display_name": "Jane Doe",
  "email": "jane@gmail.com",
  "merged": true
}
```

**How guest→Google merge works:**
The guest user ID is preserved. The account gets upgraded with
firebase_uid, email, and provider="google". All game history and
rating are retained.

#### `GET /auth/me`
Get your profile. Requires `Authorization: <token>` header.

### Leaderboard

#### `GET /leaderboard?limit=50`
Returns top players sorted by Elo rating.

```json
{
  "leaderboard": [
    {
      "rank": 1,
      "user_id": "...",
      "display_name": "GrandMaster",
      "rating": 1847,
      "games_played": 142,
      "wins": 98,
      "losses": 44
    }
  ],
  "total": 50
}
```

---

### Matchmaking

#### `POST /matchmaking/join`
Join the matchmaking queue. **Long-polls up to 30 seconds** waiting for an opponent.

```json
// Matched immediately or within 30s:
{
  "status": "matched",
  "game_id": "game-1715000000000",
  "color": "white"
}

// Still searching after 30s (call again):
{
  "status": "queued",
  "message": "3 player(s) in queue"
}
```

#### `POST /matchmaking/leave`
Remove yourself from the queue.

---

### Game

#### `POST /game/bot`
Start a game against the bot. You play white.

```json
// Response 201
{ "game_id": "game-1715000000001", "color": "white" }
```

#### `GET /game/:id`
Get current game state (board, turn, status).

#### `POST /game/:id/resign`
Resign from the game.

---

### WebSocket — Real-time Gameplay

Connect to:
```
ws://localhost:8080/ws?token=<jwt>&game_id=<game_id>
```

**On connect:** Server immediately sends current game state.

#### Messages from Server → Client

```jsonc
// Current board state (sent on connect and after every move)
{
  "type": "state",
  "payload": {
    "game_id": "game-123",
    "board": [[0,1,0,1,...], ...],  // 8x8 array
    "turn": "white",
    "status": "in_progress",
    "your_color": "white",
    "last_move": { "from_row": 5, "from_col": 0, "to_row": 4, "to_col": 1, "jumped": false }
  }
}

// Game over
{
  "type": "game_over",
  "payload": { "winner": "white", "reason": "no_moves" }
}

// Rating change (after multiplayer game ends)
{
  "type": "rating_update",
  "payload": { "delta": 15, "new_rating": 1215 }
}

// Error
{ "type": "error", "payload": { "message": "not your turn" } }
```

#### Messages from Client → Server

```jsonc
// Make a move
{
  "type": "move",
  "payload": { "from_row": 5, "from_col": 0, "to_row": 4, "to_col": 1 }
}

// Resign
{ "type": "resign" }

// Keepalive
{ "type": "ping" }
```

**Board encoding:**
```
0 = empty
1 = white regular piece
2 = black regular piece
3 = white king
4 = black king
```

## Elo Rating System

Matches chess.com's tiered K-factor:

| Games Played | K-Factor |
|---|---|
| < 30 | 40 (new player, rating changes faster) |
| ≥ 30, rating < 2400 | 20 |
| rating ≥ 2400 | 10 (top players, more stable) |

Starting rating: **1200**. Bot games do not affect rating.

Expected score formula: `1 / (1 + 10^((Rb - Ra) / 400))`

## Postman Testing

1. Import `checkers_postman_collection.json` into Postman
2. Set the `base_url` variable to `http://localhost:8080` (or your Render URL)
3. Run **Guest Login** first — it auto-saves the token to the collection variable
4. All authenticated requests use `{{token}}` automatically
5. Run **Start Bot Game** to get a `game_id`, then use **Get Game State**

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `PORT` | `8080` | HTTP listen port |
| `MONGO_URI` | `mongodb://localhost:27017` | MongoDB connection string |
| `DB_NAME` | `checkers` | Database name |
| `JWT_SECRET` | (required) | HMAC secret for session JWTs |
| `FIREBASE_PROJECT_ID` | `` | Firebase project (optional) |
| `GOOGLE_APPLICATION_CREDENTIALS` | `` | Path to service account JSON |
| `BOT_DEPTH` | `4` | Minimax search depth (3=easy, 5=hard) |
| `RATE_PER_SEC` | `10` | Global rate limit (req/s per IP) |
| `RATE_BURST` | `30` | Global burst size |
| `AUTH_RATE_PER_SEC` | `2` | Auth endpoint rate limit |
| `AUTH_BURST` | `5` | Auth burst size |
| `WS_RATE_PER_SEC` | `5` | WS message rate limit per connection |
| `WS_BURST` | `10` | WS burst size |
